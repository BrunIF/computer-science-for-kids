## final_final_REAL.py — сигнал, що потрібна машина часу

Коли проєкт росте, копії `game.py`, `game2.py`, `game_final.py`, `game_final_really.py` перестають бути зручною історією. Незрозуміло, що змінилося, хто це зробив і до якої версії повертатися.

**Version control system** зберігає історію змін структуровано. Git — одна з найпопулярніших таких систем.

## Repository — проєкт плюс історія

Git-репозиторій містить робочі файли та службові дані Git про історію. `git init` створює в поточній папці прихований каталог `.git`.

Не видаляй `.git`, якщо хочеш зберегти історію репозиторію.

## Commit — контрольна точка з поясненням

Commit можна уявити як збереження гри з коментарем: «додав меню». Він фіксує стан вибраних змін і має автора, час, повідомлення та унікальний ідентифікатор.

Git не робить commit автоматично після кожного натискання клавіші. Ти сам вирішуєш, коли зміна стала логічною контрольної точкою.

## Git-лабораторія: створюємо машину часу

```bash
mkdir -p ~/marko-lab/git-time-machine
cd ~/marko-lab/git-time-machine
printf 'print("Version 1")
' > app.py
git init
git status
```

Подивися також:

```bash
ls -a
```

Там з’явиться `.git`.

## Терміни однією фразою

- **Version control system** — система для збереження та організації історії змін.
- **Git** — найпоширений інструмент контролю версій.
- **Репозиторій (repository)** — проєкт плюс його збережена історія.
- **`.git`** — прихований каталог, де Git зберігає службові дані.
- **Commit** — контрольна точка змін з автором, часом, повідомленням і унікальним ідентифікатором.
- **`git init`** — команда, що створює Git-репозиторій у поточній папці.
- **`git status`** — показує стан робочого дерева й підказує наступні кроки.
