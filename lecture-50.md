## Маленькі програми можна з’єднувати

Одна з красивих ідей Unix: замість однієї гігантської програми для всього є багато маленьких інструментів. Один читає файли, інший фільтрує рядки, третій рахує.

Shell дозволяє з’єднати їх так, щоб **вивід однієї програми став входом іншої**.

## stdout і перенаправлення

Програма зазвичай має стандартний вивід — stdout. Термінал показує його на екрані, але shell може направити його у файл:

```bash
echo "hello" > note.txt
```

`>` перезаписує файл, а `>>` додає в кінець. Це важлива різниця: випадковий `>` може стерти старий вміст файлу.

## Pipe — труба між програмами

Символ `|` бере stdout зліва й подає як stdin програмі справа.

```bash
ls | grep '.py'
```

`ls` генерує список, `grep` залишає рядки, де є `.py`. Це маленький конвеєр.

## Приклади

### Приклад 1

`cat file.txt` друкує вміст файлу; `cat file.txt | grep Marko` передає текст у фільтр.

### Приклад 2

`printf 'one
two
three
' | grep t` покаже рядки, де є літера `t`.

### Приклад 3

`echo first > log.txt`, а потім `echo second >> log.txt` залишить два рядки. Якщо вдруге використати `>`, перший рядок буде перезаписано.

## Linux-лабораторія: побудуй конвеєр

```bash
mkdir -p ~/marko-lab/pipes
cd ~/marko-lab/pipes
printf 'cat.py
dog.txt
robot.py
README.md
' > names.txt
cat names.txt
cat names.txt | grep '.py'
grep '.py' names.txt > python-files.txt
cat python-files.txt
echo 'snake.py' >> names.txt
grep '.py' names.txt
```

Зверни увагу: `grep '.py' names.txt` може читати файл напряму, тому `cat ... | grep ...` не завжди потрібен. Але pipeline корисний для розуміння композиції.
