## Phishing намагається змусити тебе зробити дію

Фішингове повідомлення може лякати: «акаунт заблокують через 5 хвилин», обіцяти приз або просити терміново перейти за посиланням. Мета — змусити людину не перевіряти деталі.

Сильна навичка — не вгадати «це точно шахрай», а **зупинити дію й перевірити через незалежний канал**.

## Посилання і файл — це вхідні дані від іншого комп’ютера

Ми весь курс говоримо про дані. Файл із пошти — байти, які може обробити програма. Посилання веде до сервера, який надсилає дані. Тому невідоме джерело треба оцінювати так само уважно, як невідомий USB-пристрій.

## Приватність: публічний репозиторій справді публічний

На GitHub не слід публікувати паролі, API-токени, приватні ключі, домашню адресу, шкільні персональні дані, секретні конфігурації чи іншу приватну інформацію.

Навіть якщо секрет потім видалити з останньої версії, він міг лишитися в історії Git. Тому правило простіше: **секрети не коммітимо взагалі**.

## Приклади

### Приклад 1

Лист «терміново введи пароль за цим посиланням» — причина не клікати, а відкрити офіційний сайт звичним способом або запитати дорослого.

### Приклад 2

Файл `homework.pdf.exe` у Windows може маскуватися під документ назвою; формат і розширення треба оцінювати уважно — ми вже знаємо, що ім’я не гарантує вміст.

### Приклад 3

Повідомлення від знайомого акаунта теж не гарантує безпеки: акаунт міг бути зламаний. Незвична просьба про гроші чи код потребує перевірки іншим каналом.

## Лабораторія: тренажер «СТОП → ПЕРЕВІР → ДІЙ»

Прочитай три вигадані повідомлення й для кожного скажи, що робитимеш:

1. «Ти виграв консоль! Увійди тут за 2 хвилини!»
2. «Марко, я надіслав домашнє завдання. Перевір, будь ласка, файл у шкільній системі».
3. «Я твій друг, надішли мені код, який щойно прийшов тобі SMS».

Алгоритм:

```text
СТОП → не вводь секрети й не відкривай поспіхом
ПЕРЕВІР → хто відправник, яка адреса, чи очікував ти це
ПІДТВЕРДЬ → через офіційний сайт або дорослого
ДІЙ → лише після перевірки
```

## Місія для Марка

Виконай місію по черзі. Якщо щось не виходить — спочатку перечитай приклад вище й спробуй знайти, на якому кроці результат відрізняється.

1. розбери три тренувальні повідомлення
2. придумай два власні безпечні й два підозрілі сценарії
3. склади список «ніколи не коммічу в Git»
4. поясни, чому видалити секрет з останньої версії репозиторію може бути запізно
5. сформулюй свій короткий алгоритм дій при підозрілому посиланні

## Перевір себе

- Чому знайомий відправник не дає 100% гарантії?

## Терміни однією фразою

- **Phishing** — спосіб обману, коли просять ввести дані або завантажити щось із підозрілого джерела.
- **Фішингове повідомлення** — повідомлення, мета якого — змусити зробити дію.
- **Незалежний канал** — окремий спосіб перевірки (наприклад не через те саме посилання).
- **Секрети** — паролі, API-токени, ключі — те, що не слід коммітити в репозиторій.
- **Git history** — усі збережені версії комітів; видалення з останнього не гарантує зникнення.
- **Алгоритм «СТОП → ПЕРЕВІР → ПІДТВЕРДЬ → ДІЙ»** — послідовність безпечних дій при підозрі.
