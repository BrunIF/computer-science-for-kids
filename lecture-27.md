## Що ми сьогодні розкриємо

- зрозуміти, чому існує привілейований користувач
- розуміти роль `sudo`
- сформувати безпечні правила роботи з адміністративними командами

## Правило лабораторії

Команди з `sudo` виконуємо тільки тоді, коли розуміємо кожне слово команди й знаємо, навіщо потрібні підвищені права. Для навчання Марко погоджує такі кроки з дорослим.

## root має майстер-ключ

Звичайний користувач має обмеження, які захищають систему від випадкових змін. Користувач **root** має дуже широкі права. Це корисно для адміністрування і небезпечно для помилок.

Аналогія: у тебе є ключ від своєї кімнати, а в адміністратора будинку — майстер-ключ. Майстер-ключ не носять у руці для кожної дрібниці.

## sudo — виконати конкретну команду з підвищеними правами

У Ubuntu/Debian часто використовують `sudo command`. Система перевіряє, чи користувачу дозволено це робити, і може запросити пароль.

`sudo` не робить команду «кращою» або «правильнішою». Воно лише дає їй більше повноважень. Помилка з `sudo` може бути серйознішою.

## Правило найменших привілеїв

Хороший принцип безпеки: використовуй лише ті права, які реально потрібні для задачі. Якщо `ls`, `cat` або твій Python-скрипт працюють без `sudo`, додавати `sudo` не треба.

## Приклади

### Приклад 1

`whoami` під звичайним сеансом показує твого користувача. `sudo whoami` у налаштованій системі зазвичай покаже `root` — це безпечний демонстраційний приклад, бо команда лише друкує ім’я.

### Приклад 2

Для читання власного `~/marko-lab/note.txt` `sudo` не потрібен.

### Приклад 3

Встановлення системного пакета через `apt` змінює системні каталоги, тому зазвичай потребує підвищених прав.

## Linux-лабораторія: спостерігаємо права без небезпечних змін

За дозволом дорослого:

```bash
whoami
sudo whoami
```

Після цього повернися до звичайної команди:

```bash
whoami
```

Ми **не запускаємо випадкові команди через sudo**. У наступній лекції використаємо його для зрозумілої задачі встановлення пакета.

## Що потрібно винести з лекції

- root має широкі системні повноваження
- sudo тимчасово дає конкретній команді підвищені права
- адміністративні права треба використовувати лише коли зрозуміло навіщо
