# Лекція 47. `.gitignore` і цифрова гігієна репозиторію

> **Рівень 8: Хранитель історії коду**
>
> Марко, сьогодні ми не просто вивчимо новий термін — ми відкриємо ще один шар того, як насправді працює комп’ютер.

## Що ми сьогодні розкриємо

- зрозуміти, навіщо Git ігнорує частину файлів
- створити `.gitignore`
- не плутати ignore із захистом секретів, які вже потрапили в історію

## Не кожен файл проєкту треба зберігати в Git

Програми створюють кеші, тимчасові файли, локальні налаштування, віртуальні середовища, логи. Вони можуть бути потрібні на твоєму комп’ютері, але не в історії проєкту.

`.gitignore` містить шаблони шляхів, які Git не повинен пропонувати як нові untracked-файли.

## Типові Python-приклади

Для простого Python-проєкту можна ігнорувати:

```gitignore
__pycache__/
*.pyc
.venv/
.env
```

Але правила залежать від проєкту. Не треба копіювати величезний `.gitignore`, не розуміючи, що він приховує.

## gitignore не стирає історію

Якщо секрет уже був committed, додавання його імені до `.gitignore` не видалить секрет із попередніх commits. У реальній ситуації такий секрет треба вважати скомпрометованим, замінити/відкликати й окремо очищати історію за потреби.

Тому головне правило з лекції 42 лишається: **секрети не коммітимо**.

## Приклади

### Приклад 1

Папка `__pycache__/` містить службові кеш-файли Python і зазвичай не потрібна в навчальному репозиторії.

### Приклад 2

Файл `.env` часто використовують для локальних параметрів; якщо там секрети, його не можна commit-ити.

### Приклад 3

`git status --ignored` може показати й проігноровані файли, що корисно для перевірки правил.

## Git-лабораторія: чистий репозиторій

У навчальному repo:

```bash
printf '__pycache__/
*.pyc
.venv/
.env
' > .gitignore
mkdir -p __pycache__
touch __pycache__/fake.pyc
touch .env
git status
git status --ignored
git add .gitignore
git commit -m "Add gitignore for local files"
```

Файл `.env` тут порожній і лише навчальний. Не записуй у нього справжні ключі.

## Місія для Марка

Виконай місію по черзі. Якщо щось не виходить — спочатку перечитай приклад вище й спробуй знайти, на якому кроці результат відрізняється.

1. створи `.gitignore` з лабораторії
2. перевір `git status` і `git status --ignored`
3. додай власний нешкідливий шаблон, наприклад `*.log`
4. створи `debug.log` і перевір, що Git його ігнорує
5. поясни, чому `.gitignore` не врятує секрет, який уже потрапив у старий commit

## Перевір себе

- Для чого `.gitignore`?
- Чи видаляє він файл із диска?
- Чи очищає він старі commits?
- Навіщо ігнорувати `__pycache__`?
- Що робити із секретом, який уже був опублікований?

## Що потрібно винести з лекції

- `.gitignore` тримає службові й локальні файли поза новими commits
- ignore не є системою секретного зберігання
- чистий репозиторій легше читати, перевіряти й публікувати

---

**Хакерський принцип:** не запам’ятовуй магічні слова. Намагайся пояснити своїми словами, що відбулося і чому.
