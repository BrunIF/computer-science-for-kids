## Програма — рецепт на диску, процес — виконання зараз

Файл `game.py` може лежати на SSD і нічого не робити. Коли ти запускаєш `python3 game.py`, ОС створює **процес** — живий екземпляр виконання з власним станом, пам’яттю та ідентифікатором.

Один файл програми можна запустити кілька разів — з’являться кілька процесів.

## PID — номер процесу

ОС дає процесам числові ідентифікатори — **PID**. Це дозволяє інструментам говорити саме про потрібний процес, навіть якщо кілька програм мають схожі назви.

## Процеси приходять і йдуть

Процес має життєвий цикл: створюється, виконується, може чекати введення або ресурсу, а потім завершується. Після завершення програма-файл залишається на диску.

## Приклади

### Приклад 1

`program.py` — файл. `python3 program.py` — команда запуску, після якої з’являється процес Python.

### Приклад 2

Якщо відкрити два вікна калькулятора, це можуть бути два окремі процеси однієї програми.

### Приклад 3

`ps` показує процеси, а `top` — динамічний список активності системи.

## Linux-лабораторія: знайди живу програму

Створи:

```python
# sleeper.py
import time
print("Я працюю 60 секунд")
time.sleep(60)
```

У першому терміналі:

```bash
python3 sleeper.py
```

У другому:

```bash
ps aux | grep '[s]leeper.py'
```

Знайди PID. Дочекайся завершення й повтори пошук: процес має зникнути, а файл `sleeper.py` — залишитися.

## Терміни однією фразою

- **Програма** — файл із інструкціями, що лежить на диску.
- **Процес** — запущений, «живий» екземпляр програми зі своєю пам’яттю та станом.
- **PID (Process ID)** — унікальний числовий номер процесу.
- **Життєвий цикл процесу** — створення → виконання → завершення.
- **`ps`** — команда перегляду процесів.
- **`top`** — команда динамічного перегляду активності системи.

## Що потрібно винести з лекції

- файл програми — збережені інструкції, процес — їхнє активне виконання
- кожен процес має PID
- ОС керує життєвим циклом багатьох процесів
