## Git і GitHub — не одне й те саме

**Git** — система контролю версій, яка працює локально. **GitHub** — онлайн-сервіс для зберігання Git-репозиторіїв і співпраці.

Ти можеш роками використовувати Git без GitHub. Існують також інші Git-хостинги.

## remote — ім’я віддаленого репозиторію

Локальний репозиторій може знати адресу віддаленого. Типове ім’я `origin` — просто домовленість, а не магічне слово.

`git push` надсилає локальні commits у remote, а `git pull` зазвичай отримує й інтегрує віддалені зміни. За цими короткими словами стоять окремі Git-механізми, які пізніше можна вивчати глибше.

## Публікація = перевірка приватності

Перед push завжди запитай: «Чи є тут секрети, приватні дані, великі випадкові файли?» GitHub — не місце для токенів, паролів або персональної інформації.

Для дитячого акаунта та публікації репозиторіїв налаштування облікового запису, приватності й автентифікації робимо разом із батьком/опікуном.

## Приклади

### Приклад 1

`git remote -v` показує налаштовані remotes.

### Приклад 2

Типовий перший зв’язок із уже створеним порожнім GitHub-репозиторієм: `git remote add origin ...`, потім push відповідної гілки.

### Приклад 3

README у GitHub корисний не лише людям: він змушує автора сформулювати, що робить проєкт і як його запустити.

## Git/GitHub-лабораторія: публікуємо тільки безпечне

Спочатку локально:

```bash
cd ~/marko-lab/git-time-machine
git status
git log --oneline
git remote -v
```

Далі разом із дорослим створіть **порожній** репозиторій на GitHub. GitHub покаже точну remote URL. Після перевірки файлів:

```bash
git branch -M main
git remote add origin ВАША_REMOTE_URL
git push -u origin main
```

Спосіб автентифікації залежить від налаштувань GitHub; не вставляй токени в команди, файли курсу або README.

## Місія для Марка

Виконай місію по черзі. Якщо щось не виходить — спочатку перечитай приклад вище й спробуй знайти, на якому кроці результат відрізняється.

1. перед push виконай `git status` і переглянь список файлів
2. переконайся, що в репозиторії немає секретів чи персональних даних
3. разом із дорослим створи remote на GitHub і підключи його
4. виконай перший push
5. поясни словами різницю між commit і push

## Що потрібно винести з лекції

- Git зберігає локальну історію, GitHub може бути віддаленим хостингом
- push не створює локальний commit — він передає вже створену історію
- публікація коду вимагає перевірки приватності
